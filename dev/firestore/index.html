Firebase.firestore_batchget — Method

firestore_batchget(batch)

Gets multiple documents. batch is a BatchGetDocumentsRequest body, e.g. Dict("documents" => ["projects/<id>/databases/(default)/documents/<path>", ...]). Documents returned by this method are not guaranteed to be returned in the same order that they were requested.

Example

init("[FIREBASE_ADMIN_SDK].json")
pid = projectid()
res = firestore_batchget(Dict("documents" => [
    "projects/$pid/databases/(default)/documents/users/alice",
]))

Firebase.firestore_batchwrite — Method

firestore_batchwrite(batch)

Applies a batch of write operations. The documents.batchWrite method does not apply the write operations atomically and can apply them out of order. Method does not allow more than one write per document. Each write succeeds or fails independently. See the BatchWriteResponse for the success status of each write.

If you require an atomically applied set of writes, use documents.commit instead.

Example

init("[FIREBASE_ADMIN_SDK].json")
pid = projectid()
res = firestore_batchwrite(Dict("writes" => [Dict("update" => Dict(
    "name" => "projects/$pid/databases/(default)/documents/users/alice",
    "fields" => Dict("first" => Dict("stringValue" => "Alice")),
))]))

Firebase.firestore_commit — Function

firestore_commit(transactionid="", body=Dict())

Commits a transaction, while optionally applying the writes in body (Dict("writes" => [...])).

Example

init("[FIREBASE_ADMIN_SDK].json")
data = firestore_beginTransaction()

Firebase.firestore_getcollectionids — Method

firestore_getcollectionids(url; pagesize=300, pagetoken="")

Lists the collection IDs directly underneath the document at url. Returns the raw response: "collectionIds" and, when there are more results, "nextPageToken", which can be passed back as pagetoken to fetch the next page.

Example

init("[FIREBASE_ADMIN_SDK].json")
firestore_getcollectionids("/firebase_test/firebase_post")

Firebase.firestore_partitionquery — Function

firestore_partitionquery(url)

Partitions a query by returning partition cursors that can be used to run the query in parallel. The returned partition cursors are split points that can be used by documents.runQuery as starting/end points for the query results.
